# Example data reference

## Reserved values

Never use a real domain, email address, phone number, person's name, street address, or credential in an example; use a reserved or fictional value instead.
For a domain name, use `example.com`, `example.org`, or `example.net`.
For an email address, pair a reserved domain with a fictional given name, such as `dana@example.com`; a generic address like `support@example.net` works too.
For an IPv4 address or range, use `192.0.2.0/24`, `198.51.100.0/24`, or `203.0.113.0/24`.
For an IPv6 address, use a value under the `2001:db8::` range.
For a phone number, use a US number between `800-555-0100` and `800-555-0199`; never a real one.
For a fictional street address, invent one clearly outside any real numbering scheme rather than reusing a real address.
For a company name, use a generic placeholder such as "Example Organization," and add a short descriptor when two fictional companies need to be told apart.
For a project or service name, choose something meaningful to the scenario, such as `staging` or `backend-development`, rather than an unclear placeholder like `foo`, `bar`, or `baz`.

## People and identifiers

For a unique numeric identifier, such as a service account ID, use a long placeholder number rather than a short round one that looks deliberately fake, such as `123456789012345678901`.
Draw example person names from a broad, varied list rather than reusing the same one or two names everywhere, and default to gender-neutral pronouns unless gender is essential to the example.

## Filenames

Name files and directories in lowercase, with hyphens rather than underscores between words, using only plain ASCII letters, digits, and hyphens.
When a directory already uses underscores throughout, match that convention for a new file in the same directory instead of mixing styles.
When referring to a file in text, put its name in code font, follow it with the word "file," and use its exact spelling even if that spelling breaks the naming convention above.
When referring to a file type rather than a specific file, use the type's formal name, such as "a PNG file," not its extension, as in "a `.png` file."
Never use a file type as if it were a verb; write "extract the archive," not "unzip the archive."
