# Word choice reference

## Words to avoid

Replace the following words and phrases wherever they show up in engineering prose.

| Avoid | Use instead |
| --- | --- |
| abort, kill, terminate | stop, exit, cancel, end |
| access (as a verb) | name the specific action instead |
| actionable | delete; state the specific action instead |
| allows you to | lets you |
| and so on, etc. | delete; word the introduction so the list reads as a sample |
| as of this writing, currently | delete; describe the current state directly |
| now, soon, eventually, in the future | delete; describe the current state directly |
| new, latest | delete, or anchor the claim to a date or version |
| blacklist, whitelist | denylist, allowlist |
| check, uncheck | select, clear |
| click on | click |
| comprise | consist of, contain, include |
| could, would, should | can, might, must |
| desire | want |
| e.g., i.e. | for example, that is |
| easy, easily, simple, simply | delete |
| just, quickly | delete |
| enable | turn on, or name the specific action |
| execute | run |
| grayed-out | unavailable |
| hit | click, press, type |
| hover | hold the pointer over |
| impact (as a verb) | affect |
| in order to | to |
| leverage, utilize | use |
| let's | delete |
| master, slave | primary, replica |
| may | can or might, unless it grants permission |
| performant | state the specific, measurable claim instead |
| please, please note | delete |
| sanity check | quick check |
| spin up | create, start |
| surface (as a verb) | expose, show |
| via | through, by |
| we, our | you, or name the actor directly |
| while | although, when, or a plain description of simultaneous time |
| wish | want |

## Spelling of common terms

Use the following spellings consistently rather than switching forms mid-document.

| Term | Spelling |
| --- | --- |
| backend | one word |
| frontend | one word |
| codebase | one word |
| endpoint | one word |
| hostname | one word |
| filename | one word |
| lifecycle | one word |
| namespace | one word |
| runtime | one word |
| datastore | one word |
| checkbox | one word |
| key-value pair | hyphenated |
| email | no hyphen |
| open source (noun) | two words |
| open-source (adjective) | hyphenated |
| command line (noun) | two words |
| command-line (adjective) | hyphenated |
| set up (verb) | two words |
| setup (noun) | one word |
| sign in (verb) | two words |
| login (noun) | one word |
| time out (verb) | two words |
| timeout (noun) | one word |
| on-premises | hyphenated, always with the final s |
| plug-in (adjective) | hyphenated |
| plugin (noun) | one word |
| single sign-on | hyphenated |
| drop-down | hyphenated |
| pop-up | avoid; use "dialog" instead |
| URL | all uppercase |
| ID | all uppercase |
| OK | all uppercase, never "okay" |
| boolean | lowercase |
| big-endian | hyphenated |
| error-prone | hyphenated |
| high availability (noun) | two words |
| high-availability (adjective) | hyphenated |
| load balancing (noun) | two words |
| load-balancing (adjective) | hyphenated |

A term that is spelled one way as a noun and another way as a verb or adjective keeps that distinction everywhere in a document, not just on first use.
When in doubt between two spellings, pick the form used elsewhere in the same repository and stay consistent within the page.
